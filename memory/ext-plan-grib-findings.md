# Extension example app setup — lessons from grib

Covers everything discovered while getting the `react-native-mapsforge-vtm-ext-grib`
example app to build, bundle, and render. The same patterns apply to any new vtm
layer-type extension (path-color-ramp, traffic, thermal, radar, etc.).

## 1. package.json — types field

The top-level `types` field must point to an actually-existing file. Bob build
outputs declarations under both `module` and `commonjs` subdirectories:

```json
"types": "./lib/typescript/module/src/index.d.ts",
```

The `exports` map already has per-format `types` conditions, but the top-level
field is a fallback for tooling that doesn't understand `exports`. Verify it
exists after `yarn prepare`.

## 2. android/build.gradle — parent library dependency

The extension compiles against the parent library's Java classes. Without this
dependency, javac can't resolve `Utils`, `LayerHelper`, `LayerZoomBoundsHelper`,
`MapHandleContext` (context value), or any shared classes:

```groovy
dependencies {
    // ... existing deps
    compileOnly project(':react-native-mapsforge-vtm')
}
```

Use `compileOnly` — the parent's classes are provided by the consuming app at
runtime; bundling them into the extension would cause duplicate-class errors.

## 3. android/CMakeLists.txt — codegen JNI wrapper

Autolinking needs a CMakeLists.txt in `android/`. Create a wrapper that delegates
to the codegen-generated JNI:

```cmake
cmake_minimum_required(VERSION 3.16)
add_subdirectory("${CMAKE_CURRENT_SOURCE_DIR}/generated/jni/"
                 ext_codegen_build)
```

The codegen output lives at `android/generated/jni/` (generated by bob build's
`--target codegen`).

## 4. react-native.config.js — cmakeListsPath

Tell the autolinking CLI where to find the CMakeLists.txt relative to `sourceDir`:

```js
module.exports = {
  dependency: {
    platforms: {
      android: {
        sourceDir: './android',
        cmakeListsPath: 'CMakeLists.txt',
        packageImportPath: 'import com.example.ExamplePackage;',
        packageInstance: 'new ExamplePackage()',
      },
    },
  },
};
```

Without `cmakeListsPath`, the CLI generates a fallback path
(`android/build/generated/source/codegen/jni/CMakeLists.txt`) that doesn't match
where bob build outputs codegen (`android/generated/jni/`).

## 5. Autolinking cache — force regeneration

After changing `react-native.config.js`, delete the cached autolinking.json or
the autolinking CMake won't pick up the new `cmakeListsPath`:

```sh
rm -rf example/android/build/generated/autolinking
```

Then rebuild. Gradle's `generateAutolinkingNewArchitectureFiles` task re-runs and
generates correct `add_subdirectory()` calls.

## 6. Linking libraries into the example app

Three libraries need to resolve at development time:

| Library | Method | Example package.json |
|---|---|---|
| `react-native-mapsforge-vtm` (parent) | yalc | `"file:.yalc/react-native-mapsforge-vtm"` |
| This extension | yalc OR workspace symlink | `"file:.yalc/..."` or `"workspace:*"` |

Yalc is preferred because:
- No symlink-based duplicate React issues
- Properly simulates npm package for native module resolution
- Survives `yarn install`

If using `workspace:*` with `nmHoistingLimits: workspaces` (Yarn 3), the symlink
may not be materialized. Manually create it:

```sh
ln -sf ../.. example/node_modules/this-extension-package-name
```

## 7. Duplicate React — the hardest problem

When a workspace library is symlinked (not yalc-copied), Metro follows the
symlink's real path when resolving imports. This means `import ... from 'react'`
inside the library resolves to the library's own `node_modules/react` instead of
the example app's single instance. Same version, different object → hooks return
`null` → "Cannot read property 'useContext' of null".

### Solution A: yalc everywhere (preferred)

Use yalc for all libraries. No symlinks → no resolution confusion. Metro
resolves everything through `example/node_modules/`. The bob metro-config
replacement pattern (blockList + extraNodeModules) handles peer deps.

### Solution B: symlinks in root node_modules (when using workspace:*)

If the extension uses `workspace:*` (symlink), create symlinks in the root
workspace's `node_modules/` pointing to example's copies:

```sh
cd root/node_modules
rm -rf react react-native react-native-mapsforge-vtm
ln -sf ../example/node_modules/react react
ln -sf ../example/node_modules/react-native react-native
ln -sf ../example/node_modules/react-native-mapsforge-vtm react-native-mapsforge-vtm
```

Add a `postinstall` script to auto-recreate after `yarn install`:

```json
"scripts": {
    "postinstall": "node -e \"['react','react-native','react-native-mapsforge-vtm'].forEach(m=>{const t='node_modules/'+m,s='example/'+t;require('fs').existsSync(s)&&!require('fs').lstatSync(t).isSymbolicLink()&&(require('fs').rmSync(t,{recursive:true,force:true}),require('fs').symlinkSync(require('path').relative(require('path').dirname(t),require('path').resolve(s)),t,'dir'))})\""
}
```

### Solution C: Metro config with blockList + extraNodeModules (bob pattern)

Used by `react-native-mapsforge-vtm-ext-path-color-ramp`'s existing metro.config.js.
Not used by grib (which uses `resolveRequest` → ran into SHA-1 issues).

```js
const modules = [
  '@react-native/assets-registry',
  ...Object.keys(pkg.peerDependencies),  // react, react-native, react-native-mapsforge-vtm
];

module.exports = {
  resolver: {
    blockList: exclusionList(
      modules.map(m =>
        new RegExp(`^${escape(path.join(root, 'node_modules', m))}\\/.*$`)
      )
    ),
    extraNodeModules: modules.reduce((acc, name) => {
      acc[name] = path.join(project, 'node_modules', name);
      return acc;
    }, {}),
  },
};
```

### What didn't work for grib

- **Metro `extraNodeModules` alone** — without blockList, the walk-up resolution
  finds the root's copy first
- **Metro `resolveRequest`** — returning `{ type: 'sourceFile', filePath }` for
  packages causes SHA-1 errors ("file is not watched")
- **Removing `react`/`react-native` from root** — `yarn install` restores them;
  the postinstall script is needed to auto-symlink

## 8. Metro config — watchFolders

Both the extension's root and the parent library's dev directory must be in
`watchFolders` so file changes are detected:

```js
const root = path.resolve(__dirname, '..');
const parentRoot = path.resolve(__dirname, '../../react-native-mapsforge-vtm');

module.exports = {
  ...config,
  watchFolders: [...(config.watchFolders ?? []), root, parentRoot],
};
```

## 9. example/tsconfig.json

Create a tsconfig that:
1. Uses `react-jsx` (automatic JSX runtime — RN 0.86 default)
2. Has `paths` mapping to the extension's source types
3. Includes both `src` (example) and `../src` (extension source)

```json
{
  "extends": "./node_modules/@react-native/typescript-config/tsconfig.json",
  "compilerOptions": {
    "jsx": "react-jsx",
    "paths": {
      "extension-package-name": ["../src/index"]
    }
  },
  "include": ["src", "../src"]
}
```

Use a relative path for `extends` — the package name (`@react-native/typescript-config`)
may not resolve in the IDE depending on the workspace setup and `moduleResolution`.

## 10. Data URL for physical devices

`10.0.2.2` only works on the Android emulator. On a physical device, use the
machine's LAN IP:

```ts
// Emulator:
const DATA_URL = 'http://10.0.2.2:8000/sample-wind.json';
// Physical device:
const DATA_URL = 'http://192.168.x.x:8000/sample-wind.json';
```

## 11. check list for any new extension

When scaffolding a new vtm extension example:

- [ ] `package.json` `types` field — exists and points to actual file
- [ ] `android/build.gradle` — `compileOnly project(':react-native-mapsforge-vtm')`
- [ ] `android/CMakeLists.txt` — wrapper that includes `generated/jni/`
- [ ] `react-native.config.js` — `cmakeListsPath: 'CMakeLists.txt'` in android platform
- [ ] `example/metro.config.js` — watchFolders includes root + parent dev dir
- [ ] `example/tsconfig.json` — `react-jsx`, `paths`, `include` both src dirs
- [ ] Library linked in example (yalc `file:.yalc/...` or workspace symlink)
- [ ] Delete `example/android/build/generated/autolinking/` to regenerate autolinking
- [ ] No duplicate React: yalc everywhere OR symlinks in root `node_modules/` + postinstall
- [ ] Data URLs use correct host (LAN IP for physical device, `10.0.2.2` for emulator)
- [ ] `yarn prepare` (bob build) run before `yarn example android`
